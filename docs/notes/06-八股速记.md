## 一、真实素材为什么会崩（DeepSeek 场景①）

**Q1 ★ 为什么 AI 写的「视频翻译」代码在真实素材上常常跑不过 10 秒？**
- 玩具素材：单一音轨、CFR、干净容器、路径规整 → 代码只需要 happy path。
- 真实素材的变量：多音轨（要选对流）、VFR（时间轴不是常数）、硬字幕（画面已带字）、
  损坏元数据（ffprobe 直接报错）、超长时长、编码器不支持的 profile。
- 典型崩点：`-map` 没指定流号 → ffmpeg 猜错流；`-vsync` 处理不当 → 音画漂移；
  时间戳用 `frame/fps` 算而不是读真实 PTS → 长片累积漂移。
- **我们项目里的证据**：`pipeline/media/probe.py`（ffprobe 优先 + `ffmpeg -i` 兜底解析）、
  `spec/_fault.yaml` 的 corrupt_media / bad_metadata 条目。

**Q2 ★ VFR 和 CFR 有什么区别？视频处理为什么要关心？**
- CFR：帧间隔恒定，`fps` 是个真值；VFR：每帧间隔不同，`fps` 只是平均值。
- 危害：用 `i/fps` 算时间戳 → VFR 上会累积错位（0.1% 漂移 = 25 秒片长错 25ms）。
- 做法：时间轴一律以 **PTS** 为准（ffprobe `-show_frames` / PyAV 的 `frame.time`）；
  变速用 `atempo`（与帧率无关），不要用「改帧率」的方式对时长。
- 证据：`pipeline/media/probe.py` 用 `avg_frame_rate`/`r_frame_rate` 解析并保留原始值。

**Q3 ★ 多音轨素材怎么处理？**
- `ffprobe` 先列流，再**显式 `-map 0:v:0 -map 0:a:0`**；需要哪条用 `:N` 指定。
- 译制场景常见：原声轨 + 观众弹幕音轨 + 背景音乐轨 → 一般选**人声轨**做 ASR，
  背景音乐轨做混音垫底。
- 陷阱：直接 `-map 0:a` 会把所有音频流都带上 → 输出多音轨，播放器默认只放一条。

**Q4 ○ 元数据坏了怎么办？**
- 顺序：ffprobe →（失败）`ffmpeg -i` 读 stderr 兜底 →（还失败）按默认值补
  （fps=25、duration 由实际解码帧数估计）并**标注「元数据不可信」**。
- 绝不能因为探测失败就放弃整条素材。

**Q5 ★ 显存不够怎么办？**
- 降级顺序：减分辨率/帧数 → 换量化（fp16→int8）→ 换框架（torch→onnxruntime / ncnn-vulkan）→ 换方案。
- 实测门槛：LatentSync 1.6 需 18GB；ProPainter 720p 80 帧 OOM；MuseTalk 4GB 可跑但慢。
- **我们项目里的证据**：torch 是 CPU 版 → 走 CTranslate2 CPU / ONNX Runtime / ncnn-vulkan 三条路，
  见检索台账 §1。

**Q6 ★ ASR 为什么会把话听错？**
- 音频条件：背景音乐、混响、多人抢话、方言口音 → 小模型最先崩。
- 手段：VAD 先切人声段（faster-whisper 内置 Silero VAD）→ 必要时先做人声分离（demucs）
  → 换更大档位（small→medium→large-v3，CPU 上越贵越慢）→ 给 `initial_prompt` 压领域词。
- 实测：BLG VLOG 上 small 档把「开腔」听成「开空腔」；30.2s 音频推理 2.2s（RTF≈0.07）。

**Q7 ★ 时间戳为什么不能「按帧算」？ASR 给的时间戳能直接用吗？**
- whisper 类模型给的是 **VAD 切分后的相对时间**，需要加回 VAD 偏移。
- 字幕段还要做**最小显示时长/最大显示时长**处理，否则一闪而过。
- 我们的处理：直接用 segment.start/end 作为「原槽位」，TTS 回来后按槽位回贴。

## 二、怎么选模型、怎么算性价比（DeepSeek 场景②）

**Q8 ★ 同一个环节有多个方案，你凭什么选？**
- 不能凭「听说哪个好」→ 固定 case 集 × 多方案 × 多指标，**一轮跑完出一张表**。
- 指标分四类：效果（主指标）、耗时、显存/成本、失败率。
- 关键纪律：**同一指标只有一个口径**（我们踩过：同一母版在 16 帧/24 帧下算出两个正脸率，
  已统一为 `--frames 24` 并写进文档脚注）。
- 证据：`spec/*.yaml`、`docs/notes/技术选型检索台账.md`。

**Q9 ★ 降本怎么做，才不会降效果？**
- 手段：结果缓存（同一 case 同一参数不重复调）、分段合并请求（一次请求翻译多条，
  但要防止长文本丢失 → 用编号行协议 + 解析失败回退原文）、模型分级路由
  （便宜的先跑，难例升级）、离线优先（能离线的不花钱）。
- **成本要算「失败的钱」**：超时/重试的调用照样计费；我们把 token 记在 `stat.extra`，
  降级也要写进账单。
- 证据：`spec/translate.yaml`（cache/幂等键在 `_fault.yaml` 的 resumability 段）。

**Q10 ★ CER / WER / PSNR / SSIM / LSE-C 各是什么，为什么用不同指标？**
- CER：字符错误率（ASR/翻译，字符级更贴近听感）
- PSNR/SSIM：像素级相似（修复/超分，**必须分区算**，否则背景面积主导）
- LSE-C/LSE-D：SyncNet 置信度/距离（唇音同步，公认口径）
- MFVSR 口径：字幕区（擦得好不好）/ 区外（有没有误伤）/ 时序（会不会闪）三档分开报。

**Q11 ○ 量化 int8 会掉多少点？**
- CTranslate2 int8 在 CPU 上通常比 fp32 快 1.5–4 倍，CER 损失通常 <1% 绝对值；
  官方基准里 int8 与 fp32 的差距在可接受范围，但**必须在自己的 case 集上实测**。

**Q12 ★ 翻译层最常见的两个坑？**
- **漏行**：模型输出条数与输入不一致 → 漏的那条被静默丢掉 → 字幕与音频错位。
  对策：编号行协议 + 缺失回退原文 + 记 warning（我们把它做成硬契约：漏解析段数必须 = 0）。
- **长度不匹配**：译文比原句长 → TTS 塞不进原时间槽 → 必须变速，超过 ±25% 就不能硬拉
  （`overshoot` 计数 = 译文长度不匹配的量化证据）。
- 证据：`pipeline/translate/openai_compatible.py`、`pipeline/compose.py`、`spec/translate.yaml`。

**Q13 ★ TTS 怎么保证「听起来像同一个人在说话」？**
- 同一音色（voice id）贯穿全片；语种/音色必须匹配文本语种。
- 实测坑：**edge-tts 用英文音色读中文会直接抛 NoAudioReceived**（整批合成全挂）→
  我们改成按**文本实际语种**选音色并记 `voice_switched_segments`。
- 更强的方案是音色克隆（IndexTTS2），但授权与显存有限制。

## 三、口型与视频修复

**Q14 ★ 唇音同步偏移怎么客观测量？**
- 公认口径：**SyncNet**（joonson/syncnet_python，有 CPU-only 环境）→ `AV offset`（帧）×1000/fps = 毫秒，
  配 `Confidence`；Wav2Lip 的 evaluation 给 LSE-C / LSE-D。
- 帧率粒度：25fps 一帧 40ms，要更细必须插值并声明不确定度。

**Q15 ★ 能不能自己用 OpenCV 算偏移？（能，但有前提）**
- 方法：人脸框 → 嘴部 ROI → 开口度序列（唇间暗像素占比/灰度方差）↔ 音频能量包络 → 互相关取峰。
- **致命前提**：译制片的嘴型由**原音轨**驱动，与新配音不同源 → 互相关是伪峰，只能当负控。
- 其它陷阱（详见检索台账 §5）：VFR 时基、元音偏置、静音段主导、ROI 漂移、多峰歧义、归一化。
- 结论：自研探针当**回归门禁**，SyncNet 当**公认口径**，两者交叉验证。

**Q16 ★ 字幕擦除：LaMa / STTN / ProPainter 有什么区别？**
- LaMa：**图像级**修复，无时序一致性 → 运动镜头会闪。
- STTN / ProPainter：时空一致性，ProPainter 靠 RAFT 光流 + Sparse Transformer，效果最好但最吃显存
  （README 显存表：720p 80 帧必 OOM）。
- 我们的对比表：A=OpenCV inpaint（零依赖基线）vs B=video-subtitle-remover（Apache-2.0，
  内置四模式且支持纯 CPU）。
- License 坑：ProPainter 是 **S-Lab 非商用**。

**Q17 ★ 擦字幕的效果怎么评？**
- 必须在**字幕 mask 内**算 PSNR/SSIM，同时报**区外**指标防误伤，再报时序指标（TC/TWE）。
- MFVSR 的关键论点：**全图 LPIPS 会被背景面积主导，「字没擦掉也能得高分」**。
- 我们有「合成 GT 法」：母版 + 烧录字幕 = 派生件，母版即 GT → PSNR 可算。

**Q18 ★ 超分在本机能跑吗？**
- Real-ESRGAN ONNX 可 CPU 跑但逐帧视频太慢（Pi5 实测 x4plus 约 1.5 分钟/小图）；
- **ncnn-vulkan 路线**吃 GPU 且**不依赖 torch CUDA**（本机 torch 是 CPU 版，这是绕开限制的关键）；
- 对比表里 A=bicubic 基线，B=ncnn-vulkan。

## 四、B 站自己是怎么做的（面试加分，但要说清「未开源」）

**Q19 ★ 你了解 B 站官方的视频译制开源项目吗？**
- `bilibili/Index-Translate`（**Apache-2.0**，GitHub 官方组织）含 `video-dub/`：
  抽音 → demucs 人声分离 → silero-vad 切句+时间戳 → 逐句配音 → **时间轴回贴** → 音轨替换。
- 但：**画面流是 copy 不重编码 → 出的片子嘴是不动的**，且它不含字幕擦除。

**Q20 ★ 官方口型方案是什么？**
- 官方博客口径：**扩散基座 + 3D VAE（时序特征，减少唇齿抖动）+ 参考网络（注入身份特征 ID）**。
- 必须补一句：**该技术未开源**，我们只能引用口径，不能复用资产。

**Q21 ○ Index-Echo-S2TT 是什么？能用吗？**
- 真实（Apache-2.0）：**Qwen3-Omni AuT 音频编码器 + Index-Translate-2B 文本解码器**，
  输出双语字幕与句级时间戳。
- 不能用的理由：2B bf16 约 **10GB 显存**（本机 8GB）；只支持中→英/日/西，不满足英中双向。

**Q22 ○ IndexTTS 的 License 有什么坑？**
- 不是 Apache-2.0，是 **B 站自定义协议**：>1 亿 MAU 或 >10 亿营收需单独授权；
  且**禁止用其输出改进其它 AI 模型**。→ 面试提到这个会显得真读过 License。

## 五、工程、成本与可复现

**Q23 ★ 怎么保证一条流水线「敢上线」而不是「跑通 demo」？**
- 每个环节有 spec（输入输出契约 + 指标 + 阈值 + 降级路径 + 预算 + 必须跑通的 case）；
- runner 自动跑分、自动出 badcase；每行结果留痕（耗时/显存/成本/成败/降级原因）；
- 改任何方案后重跑与上一轮 diff，**只让「本来就过的 case」保持过**（回归）。

**Q24 ★ 断网了怎么办？**
- 分级：DNS 失败/连接超时 → 退避重试；429 → 退避 + 熔断；401 → 不重试（凭据问题，人来管）；
  全网不可达 → **进入离线模式**（翻译走术语表降级、TTS 保留原声），**整条流水线继续跑完并出降级成片**。
- 关键：断点续跑（每阶段产物落盘 + 幂等键 sha256(case+stage+input+params)）。
- 证据：`spec/_fault.yaml` + `scripts/fault_test.py`（7 个注入用例全过）。

**Q25 ★ 为什么降级必须留痕？**
- 因为降级后**部分质量指标失去意义**（没配音 → 唇音同步无意义）。静默降级会让跑分表失真，
  最终是「数字漂亮但片子不能看」—— 这正是 JD 要我们避免的。
- 字段：stage/provider/model/elapsed_ms/degraded/error/attempts；**凭据与 Authorization 永不落盘**。

**Q26 ★ 接内网 / 拿公司账号串接口，实际要注意什么？**
- 凭据只从配置/密钥管理读，**绝不进代码、绝不进日志**（我们：`.env` + `describe()` 只输出脱敏视图）。
- 统一网关接口：外部 API 走公司网关时，Pipeline 只认协议（我们：OpenAI 兼容层），
  换端点只改 base_url + key，不改业务代码。
- 审计：谁、何时、哪个 case、用了哪个模型、花了多少 token → `results/<run_id>/audit.jsonl`。
- 限流/熔断/灰度：网关侧限流要在客户端体现为退避与熔断，而不是把错误直接抛给用户。

**Q27 ★ 怎么保证结果可复现？**
- 版本（依赖清单）、输入（SHA256）、参数、随机种子、模型版本全部留痕；
  素材入库时记 SHA256（我们 `_work/blg_fetch.py` 就这么做）。

**Q28 ○ Linux/Windows 上的坑？**
- Windows：路径含 `!` 时 Git Bash 会出错（用户目录操作要用 PowerShell）；中文路径；
  `cv2.data.haarcascades` 在 opencv 5.0 变成空目录（级联文件要另下）；
  `dnn` 模块读不了非 ASCII 路径。

## 六、在模糊中推进与担责（DeepSeek 场景④）

**Q29 ★ 业务方说「翻译出来的视频没人看」，你怎么排查？**
- 分层归因（不要一上来改模型）：
  1. **断句**：字幕切在哪、有没有把一句话切两半 → 看 ASR 段边界与译文行数；
  2. **口型**：嘴和音对不上（用 SyncNet offset 佐证，而不是凭感觉）；
  3. **翻译腔**：术语是否命中、长度是否超槽（Δt / overshoot）；
  4. **技术层**：字幕是否遮挡、音量是否突变、变速是否失真。
- 结论要落到「改哪个 Prompt / 哪段 Pipeline 逻辑」，并给出改前改后的指标对比。

**Q30 ★ badcase 怎么分诊？什么时候该退回、什么时候该放行？**
- 分类：**模型不行** / **素材本身不可解** / **环境限制** / **我们的代码有 bug** —— 四类的处理完全不同，
  第三类不该让模型背锅，第四类是我们的责任。
- 放行判据由业务定（人眼 + 指标双阈值）；模型不行 → 换方案或升级模型；
  素材不可解 → 记录并向上反馈（这正是职责 4「推动优化」）。

**Q31 ★ 为什么「模型能跑通」和「敢上线」差一层？**
- 差在：**什么算合格**（阈值）、**这个 badcase 能不能放行**（判断+担责）、
  **结论能不能让算法/产品/研发接受并去改**（推动人）。
- 这三件都不是「生成」，是「判断 + 责任」，所以必须有人。

**Q32 ★ 如果让你用 300 元/天的预算雇一个人 vs 充 AI 额度，你选哪个？**
- 纯代码产出上，AI 完胜（300 元 ≈ 1500 元/月 ≈ 一次订阅）。
- 人赢在五点：①没有 spec 的部分 AI 只会猜阈值；②badcase 放行是担责不是生成；
  ③职责 4 的对象是人，agent 不能开会背锅；④**失败成本不对称**（AI 错一次废一批片子，人错一次拦住一批）；
  ⑤**AI 的真实成本不是 token 是返工轮次**——我们自己的硬字幕检测器就写了两版才收敛
  （v1 在自造样本上假阴性、在暗帧上假阳性，v2 改成「整帧中位数 + 绝对下限」才过）。
- 判据：**只有当活里存在「没有 spec 的部分」才值得雇人；90% 是照明确 spec 实现，就该充额度。**
