# 接入层与网关实践

> 对应用户提的第三点：「拿着公司的账号，去串联内部的接口，或者把外部 API 接入公司的网关」。
> 以及 JD 里的可讲点：**多供应商管理、鉴权与凭据治理、限流熔断、请求审计**。

---

## 0. 一句话结论

**凭据只从环境变量读，永远不进代码与日志；每次调用留一行审计；限流退避、熔断快速失败。**
本地用 `scripts/mock_gateway.py` 复现了公司网关最常见的四种行为
（401 鉴权失败 / 429 限流 / 403 模型白名单 / 正常转发），接入层对这四种的处理全部可验证。

---

## 1. 这一层解决什么

公司场景下，模型调用不是「拿自己的 key 直连 DeepSeek」，而是：

```
我们的流水线
   │  Authorization: Bearer <公司账号签发的 token>
   ▼
公司统一网关  ──▶ 外部 API（DeepSeek / OpenAI 兼容）
   │           └▶ 内部接口（内部大模型 / 内部 ASR / 内部 TTS）
   ├─ 鉴权（我们的账号有没有权限调这个模型）
   ├─ 模型白名单（只放行被采购/批准的模型）
   ├─ 限流（QPS/RPM 配额）
   └─ 审计（公司侧要能查「谁、什么时候、花了多少 token」）
```

所以接入层要做的**只有 5 件事**，多一个都是过度设计：

| # | 职责 | 实现 | 为什么必须 |
|---|---|---|---|
| 1 | 凭据治理 | 只从环境变量读；日志里以 **sha256 前 8 位指纹**出现 | key 落盘 = 事故；指纹仍可对账「是不是同一把 key」 |
| 2 | 模型白名单 | 本地先拦，不在白名单 → 0ms 拒绝 | 省一次往返；也避免把「不该调的模型」记到公司账上 |
| 3 | 限流 | 客户端侧每分钟配额 + 最小间隔 | 别把公司网关打挂 |
| 4 | 重试与退避 | 尊重 `Retry-After`；**401/403 不重试** | 错 key 重试一万次也是错 |
| 5 | 熔断 | 连续失败 N 次 → 打开，快速失败，冷却后半开 | 拖死整条流水线不如早点失败并降级 |

**请求体/响应体默认不落盘**（审计只记元数据）—— 这是「可审计」与「不泄密」的分界。

## 2. 代码位置

| 文件 | 作用 |
|---|---|
| `pipeline/gateway/audit.py` | 审计日志（JSONL）+ 脱敏 `redact()` + 凭据指纹 `fingerprint()` |
| `pipeline/gateway/client.py` | 网关客户端：白名单 / 限流 / 重试退避 / 熔断 / 审计 |
| `scripts/mock_gateway.py` | 本地假网关：复现 401 / 429 / 403 白名单 / 正常转发 |
| `scripts/gateway_demo.py` | 接入层演示脚本，逐条打出上面四种路径的处理结果 |

配置（**全部环境变量，代码里没有明文密钥**）：

```
GATEWAY_BASE_URL        网关地址（OpenAI 兼容路径前缀，如 https://gw.corp/v1）
GATEWAY_API_KEY         公司签发的 token
GATEWAY_UPSTREAM_BASE_URL  需要转发到外部 API 时的上游地址（留空=网关自处理）
GATEWAY_ALLOWED_MODELS  逗号分隔的白名单模型
GATEWAY_RPM             客户端限流（次/分钟，0=不限）
GATEWAY_TIMEOUT         单次请求超时秒
GATEWAY_MAX_RETRIES     重试次数
GATEWAY_BREAKER_THRESHOLD / GATEWAY_BREAKER_COOLDOWN   熔断阈值与冷却
GATEWAY_AUDIT_PATH      审计日志路径
GATEWAY_ACTOR           审计里的操作者标识（谁的账号）
```

## 3. 实测结果（本地 mock 网关，可复现）

```bash
# 终端 1
python scripts/mock_gateway.py --port 8790 --rpm 3
# 终端 2
python scripts/gateway_demo.py --burst 1          # 正常路径
python scripts/gateway_demo.py --model not-approved-model   # 白名单拒绝
python scripts/gateway_demo.py --wrong-token               # 401
python scripts/gateway_demo.py --burst 5                   # 触发 429 + 退避
```

| 场景 | 结果 | 耗时 | 处理 |
|---|---|---|---|
| 正常 | OK | 38ms | 返回内容 + token 计量 |
| 模型不在白名单 | `FAIL(blocked)` | **0ms** | **本地拦截**，没发出去 |
| token 不对 | `FAIL(auth)` | 153ms | **不重试**（重试无意义），直接报鉴权失败 |
| 连续 5 次、rpm=3 | 3 OK → 1 次 `429` → 之后 OK | 429 那次等了 **58.9s** | 尊重 `Retry-After`（mock 返回 60s）→ 退避后成功 |

审计日志（每行一条，**没有任何凭据明文**）：

```json
{"ts":"2026-11-25T18:21:44+0800","actor":"demo","kind":"model_call","stage":"gateway_demo",
 "case_id":"demo_0","model":"deepseek-chat","status":"ok","latency_ms":35,
 "tokens":{"prompt":5,"completion":5,"total":10},"error":null,"extra":{}}
```

`cfg.describe()` 是给报告用的脱敏视图：`key_fingerprint: aa6ab55f`，**看不到 key 本身**，
但能对账「是不是同一把 key」。

### 熔断的实测行为（修过一次）

第一版把 **429 也算进熔断计数**，结果：突发流量触发一次限流 → 连续失败 3 次 →
熔断打开 → 后续请求 14ms 内直接失败。**这是错的**：429 是对方主动限速（预期背压），
不是网关故障，不该把整条链路瘫掉。改成：**429 不计入熔断计数**，
修完后同一场景变成「3 OK → 429 退避 58.9s → 恢复 OK」，熔断始终没打开。

> 这条正好是「熔断该熔什么」的答案：**熔断熔的是「继续打也不会成功」的故障**
> （连不上、5xx、鉴权失效），**不是「对方让你慢一点」**。

## 4. 与「多供应商管理」的关系

网关接入和项目里已有的**翻译后端降级链**是两层，不是一件事：

| | 翻译后端链（`pipeline/translate/registry.py`） | 网关接入层（`pipeline/gateway/`） |
|---|---|---|
| 管什么 | **哪个模型**来翻（deepseek → 兼容端点 → 离线术语表） | **怎么调到**那个模型（凭据/白名单/限流/熔断/审计） |
| 失败表现 | 换下一个后端，段数不变、内容降级 | 同一次调用内重试/退避；仍失败才交给上层降级 |
| 留痕 | `stat.extra.attempts` | 审计 JSONL 一行一次调用 |

**串起来是这样**：网关 401 → 接入层判定「不可重试」→ 抛 `GatewayError(kind="auth")`
→ 上层翻译链记 attempt 并切下一个后端 → 最终离线降级出片。
**每一层都留痕，出问题时能一眼看出断在哪一层。**

## 5. 还没做的（诚实缺口）

| 项 | 状态 | 说明 |
|---|---|---|
| 真·公司网关对接 | ❌ 未做 | 没有公司环境/账号；这里是**按接口契约写的可替换层**，换 `GATEWAY_BASE_URL` 即接 |
| 内部接口串联（非 OpenAI 兼容形状） | 🟡 只做形状对齐 | 内部 ASR/TTS 的私有协议需要另写适配器，`GatewayClient` 只覆盖 OpenAI 兼容的 chat 形状 |
| 灰度/分流 | 🔶 未做 | 计划里提过，未实现（客户端侧按模型名路由是最简形态） |
| 审计入库（ELK / 表） | 🔶 未做 | 现在是本地 JSONL，格式是行分隔 JSON，可直接被采集 |
| 令牌轮换 | 🔶 未做 | 指纹机制留了位置，但没做双 key 切换 |
