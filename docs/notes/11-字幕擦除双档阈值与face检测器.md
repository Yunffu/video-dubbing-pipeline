# 硬字幕擦除：双档阈值口径 + 人脸字幕检测器（2026-11-25）

这一轮做了四件事：修了**评测素材本身的 bug**、补了**人脸字幕检测器**、
把**矩形 mask 打通到擦除/指标链路**、把**验收阈值改成双档**。
最后一件事不是调参，是改「用什么尺子量」。

---

## 一、素材 bug：face 派生件的字幕根本没压在脸上

`scripts/make_derived.py` 原来把 `hard_sub_face` 的字幕烧在**画面顶部**
（ASS `align=8`），不在脸上。

后果是链路的：之前 4 个 face case 全部 DEGRADED（检测器报「未检出稳定的
底部高密度带」）—— 但那不是检测器的问题，是**拿假 case 测检测器**。
如果当时不查，很容易得出「压脸字幕检测不了」的结论。

修法：`make_derived.py::detect_face_anchor()` —— 用 YuNet 逐帧检人脸 →
取中位数人脸框 + 嘴部关键点 → 字幕用 ASS `\pos(x,y)` 直接定位到嘴上，
字号按脸高 30% 取。4 个派生件已重新生成（`assets/derived/*_hard_sub_face.mp4`），
`derived.json` 里留了 `subtitle_anchor`（人脸框/嘴/字号/落点）便于复现。

## 二、人脸字幕检测器（pipeline/face_sub.py）

思路是**可解释的启发式**，不是黑盒模型：

1. YuNet 检人脸框 → 知道脸在哪；
2. 字幕压住嘴/下巴 → 只在脸下半部（face_y + 0.25h ~ +1.40h）找；
3. 脸的横向范围内做**行方向边缘密度剖面**（Laplacian 方差）→ 找文字行；
4. 文字行内做**列方向剖面** → 找文字左右边界。

### 踩过的坑

| 坑 | 现象 | 根因 | 修法 |
|---|---|---|---|
| 只找到第 1 行 | y1=453，oracle 是 480 | 两行字幕中间有空隙（≈7 行 ≈0.09 脸高），连续段被切开 | 分段后按行距 ≤0.30×脸高 合并，选**含密度峰值**的那组 |
| 列范围塌成 1px | 文字边界找不到 | 用**中位数**当背景基准，但文字本身占了搜索区 64% 的列，阈值被抬到笔画核心 | 背景基准改用 **p10** |
| 逐列切 1px 算 Laplacian | 列间数值不可比 | 3×3 核在边界上的伪影 | 先对整条带做 2D Laplacian，再按列取方差 |
| oracle 框几乎占满全屏 | bbox 完全不可用 | 单帧相减被编码噪声淹没 | 先对 9 帧逐像素差取**时间中位数**再阈值化 |
| 母版/底部字幕片误报 | 检出「压脸字幕」 | 嘴、牙齿、下巴、衣物纹理也是高密度 | 三条否决判据 |

### 三条否决判据（缺一不算压脸字幕）

- 横向跨度 ≥ 1.5×脸宽（嘴/牙齿/下巴只占 ~0.6 倍脸宽）
- 文字行必须**跨过嘴**（嘴上方的衣服/背景高对比带不算）
- 文字块高度 ≥ 0.30×脸高（实测压脸字幕 ≈0.55 倍脸高）

### 准确性怎么证明（不靠"看着对"）

用合成 GT 法造 oracle：母版 + 烧录字幕 → 两者相减 = 字幕像素的精确位置。
检测矩形与 oracle 矩形求 **IoU**，实测 **0.92–0.99**。
母版（干净）、底部字幕片作为负样本 → 全部不误报。

## 三、矩形 mask 打通到擦除/指标链路

之前底部字幕走**全宽横带**、人脸字幕没法处理。现在统一成矩形：

```
底部字幕 → (0, y0, w, y1)     ← 全宽横带
人脸字幕 → (x0, y0, x1, y1)   ← 检测出的矩形
```

`se.region_of(band, w)` 把两条路径归一，**共用同一套擦除/指标/判定链路**，
区外区域 = 掩膜补集（上下两条 + 左右两条）。

改动文件：`pipeline/subtitle_erase.py`（`make_mask_rect` / `detect_face_subtitle` /
`region_of`）、`eval/metrics.py`（`_as_rect` / `_crop` / `psnr` / `ssim`）、
`eval/runner.py`（按 difficulty_type 分流）。

结果：**4 个 face case 从全部 DEGRADED 变成全部跑通**（8/8 有指标）。

## 四、双档阈值口径（用户 2026-11-25 拍板）

### 为什么原来的「30dB / SSIM 0.9」不能用

`scripts/erase_sweep.py` 用 **oracle 完美遮罩**跑出来的**上限**是：

```
M1_04   PSNR 29.96dB / SSIM 0.50
```

也就是说 30dB 物理上达不到，SSIM 0.9 差了 0.4。若把 30/0.9 当唯一门槛，
等于「用指标逼着换方案」—— 把**选型**和**验收**混成一件事，
跑分器退化成「按方案 A 判它必挂」。

### 现在的口径（锁在 `eval/thresholds.py`，spec 里同步）

**硬约束（所有方案一视同仁，不分档）**

| 指标 | 阈值 | 含义 |
|---|---|---|
| `psnr_out_mask_delta` | ≥ -0.5 dB | 区外不能比擦之前更差 |
| `untouched_out_mask` | ≥ 60 dB | 掩膜外像素必须原封不动（理论 99dB，60 已很宽松） |

**调优项（按方案分档）**

| 档位 | 方案 | PSNR | SSIM |
|---|---|---|---|
| A | OpenCV inpaint（TELEA/NS，纯 CPU） | 25 | 0.75 |
| B | 视频修复模型（LaMa/ProPainter/STTN） | 30 | 0.90 |

**判定规则**

```
硬约束不过              → FAIL（一票否决）
硬约束过了、调优项未达本档 → WARN（不判 FAIL，记为待调优）
全部达标                → PASS
```

「调优项未达本档 = WARN」是拍板的硬规则，不设例外：调优项只回答
「离这一档还差多少」，不用来一票否决。结果表同时给 **A档 / B档 两列 ✅❌**，
「方案 A 的真实水平」和「距离方案 B 还差多少」一次看全。

对外一句话：**区外不得误伤是硬约束，字幕区 PSNR 是分档的调优项。**

## 五、两个必须写进简历/面试稿的发现

### 发现 1：口径错了，结论会反过来（已修）

旧口径「采样帧均值」下，同一条 M1_04 的字幕区 PSNR 随采样数漂移：

```
4 帧 → 16.07dB   6 帧 → 29.89dB   8 帧 → 26.46dB   12 帧 → 16.09dB
```

根因：**素材里有近黑帧**（母版整帧均亮度 ≈0）。黑帧上「擦除」= 擦完还是纯黑
→ 与母版逐像素相同 → **PSNR 恒 99dB**，采到就拉高均值。

修法三件套：① 近黑帧（母版帧均亮度 < 8）单独计数、不进主指标；
② 主指标取**中位数**；③ 同时报 p25/p75/样本数。

**这直接推翻了上一轮的结论**：`2026-11-25_eraseA_v3` 报 M1_01 = 29.87dB
「差一点就过 30dB」，实测那正是 **均值被黑帧的 99dB 拉出来的**：

```
6 帧取值（含黑帧）：[99.0, 17.83, 17.72, 15.87, 14.23, 14.57]
均值 = 29.87（旧口径）   中位数 = 15.87（新口径）
```

所以本轮 PSNR 全面下降 **不是回归，是换了正确的尺子**。为此给每行结果加了
**口径指纹**（`metric_profile` / `judge_profile`），跨 run 比较前口径不一致
会明确警告「pass/fail 不可直接比较」—— 防止再次拿不同口径的数说「变好了」。

### 发现 2：底部字幕的 mask 太宽，擦掉了 15% 的真实画面

现状：底部字幕检测出 `bands [15,18]` → 掩膜 rows 806–1030，
占画面高度 **20.7%**（mask_area_ratio）。字幕实际只在底部约 60px。

后果：多擦掉的 150px 是**真实画面内容**，inpaint 出来是拉伸/涂抹 →
字幕区 PSNR 只有 15–22dB。而同样的算法用 **oracle 完美遮罩**能到 **29.96dB**。

**所以这 15dB 的差距不是算法不行，是 mask 画得太粗。**
下一步（未做）：在已检出的横带内再做一次行密度剖面，把 mask 收到
文字实际所在的几行 —— 和 face 检测器用的方法是同一套技术。
