## 3. 官方口径（面试可引用，注明「未开源」）

B 站官方博客《B站是如何实现原声视频翻译的》/《How does bilibili achieve AI Dubbing?》（2025-08，CSDN 镜像 blog.csdn.net/bilibili_tc/article/details/150224095）原文：

> 在B站自研的技术方案中，视频编解码器采用 **3D VAE** 来提供更强的时序特征，可以减少嘴唇、牙齿的抖动；**增加了参考网络用来加强ID的生成能力**……因此，我们采用 **Diffusion模型作为生成基座**，开发了高保真、强鲁棒的口型驱动技术。

> 我们的 BILIBILI IndexTTS2 重点在视频语音翻译场景保持高精度音色克隆。

**必须同时说明**：这套口型技术**没有开源**，官方开源的 `video-dub` 管线画面流是 copy 不重编码 —— 出的片子嘴是不动的。
另：Index-Translate 官方博客与 arXiv 2609.40181 全文**无任何生产部署声明**；「上线」出自 2025-08 那篇讲 IndexTTS2 的旧文（原文：「最近，我们上线了一个新能力：支持将部分中文视频翻译为外语的原声风格配音。」）。

## 4. 评测口径参考（做对比表时用）

- **MFVSR**（arXiv:2610.18461，HF dataset `siiian/MFVSR`）主张分三档报：
  - Restoration Fidelity：字幕区 PSNR / LPIPS / DISTS
  - Preservation Fidelity：区外 PSNR / LPIPS（防误伤）
  - Temporal Fidelity：TC / TWE-Excess（区内区外分别报）
  - 关键论点：**全图 LPIPS 会被背景面积主导，「字没擦掉也能得高分」**
- **CLEAR**（arXiv:2603.21901）：mask-free 端到端，指标 PSNR / SSIM / LPIPS / DISTS / VFID / TWE / TC
- 现成可复用代码：video-subtitle-remover 的 `backend/inpaint/video/core/metrics.py`（PSNR/SSIM/VFID），
  但两点要改：**全图口径 → 加 mask 加权**；`compare_ssim(multichannel=True)` 在新版 scikit-image 已移除（改 `channel_axis=-1`）

## 5. 唇音偏移的自研探针：已知陷阱（写进报告，避免结论不可信）

1. **不同源问题（最致命）**：译制片画面嘴型由**原音轨**驱动，与新配音无因果关系 → 互相关得到伪峰，只能当负控
2. **VFR**：`cv2.CAP_PROP_POS_MSEC` 不可靠，必须用 ffprobe `-show_frames` 拿真实 PTS 建时基
3. **帧率粒度**：25fps 一帧 40ms，亚帧偏移必须插值并声明不确定度
4. **开口度 ≠ 音素**：爆破音/塞音开口度与音量弱相关，结果系统性偏向元音段
5. **时间常数不同**：音频包络需整流+低通（20–40ms）才可比
6. **静音段主导**：嘴闭合时两路都是噪声底 → 必须能量门控并报告「有效对齐时长」
7. **ROI 漂移**：镜头运动/转头时固定 ROI 会漂 → 限定「单镜头正脸」评测集并在报告写明前提
8. **多峰歧义**：周期性语音产生多个等高峰 → 要报 peak value + 次峰比 + 唯一性判定
9. **前置归一化**：零均值 + 单位方差 + 去直流

**结论**：自研探针适合当「廉价、可解释、毫秒级」的回归门禁（配合已知偏移注入的合成基准），**不能替代 SyncNet 的 LSE-C/LSE-D**。
