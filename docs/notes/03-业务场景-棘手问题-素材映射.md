**一句话业务判断**：这是一个「**给 B 站内容做多语言本地化的生产工具岗**」，

→ 所以我的项目必须产出**对比表**，不能只产出视频。

## 2. 需要处理的棘手情况（从 JD 反推，每条都对应一个可测指标）

### 2.1 时长对齐（**最核心，JD 职责 3 的真正考点**）

| 方向 | 现象 | 后果 | 需要的手段 | 对应指标 |
|---|---|---|---|---|
| 英→中 | 英文音节多、中文字少 → 译文**变短** | 译文音频提前结束 → 后面几秒口型漂移、字幕提前消失 | 静音填充 / 语速放慢 / 尾帧延长 | 段级时长偏差 Δt、尾部漂移秒数 |
| 中→英 | 中文信息密度高 → 英文展开**变长** | 译文音频超出原片 → 后面全乱 | 语速压缩 / 裁画面 / 变速视频 | 超出段占比、超出秒数 |

> 这两条方向相反，所以**单语种做不出这个结论**——必须双向都跑。这是第一版定「双向」的技术理由，不是随便选的。

### 2.2 口型同步在什么情况下会崩

| 棘手 | 为什么会崩 | 业务里对应什么 |
|---|---|---|
| **侧脸** | 嘴部关键点不可见/被压缩，模型只能外推 | 选手侧身接受采访 |
| **多人** | 检测到多张脸，脸部裁剪框会跳 | 赛后群访、主持连麦 |
| **嘴部遮挡** | 嘴被话筒/口罩/手挡住 | 现场解说、选手戴口罩 |
| **低清** | 脸小、糊，关键点定位漂移 | 直播切片、老片修复 |

### 2.3 已有硬字幕的视频要擦除重绘

源视频底部已有烧字幕 → 要先擦掉再压新语言的字幕。
难点：**不能伤到画面里的人脸/字幕栏**，擦完的区域还要**和周围背景一致**（不然像一块补丁）。

### 2.4 低质量源需要修复增强

直播切片、老片、录屏：低码率、噪声、模糊 → 要超分/去噪/稳像，且要能**证明**提升是真实的（PSNR/SSIM 对 GT）。

### 2.5 批量稳定性与降级

生产工具岗的真痛点：一次批量 100 条，中间某个 API 挂了怎么办？
→ 必须**自动降级 + 全程留痕**（哪个环节降级、什么原因、耗时多少）。

### 2.6 噪声直接打到上游 ASR

噪声 → ASR 识别错字 → 字幕错 → 唇音不同步 → **错会被下游放大**。
所以噪声不是"画质问题"，是**上游质量问题，会污染整条链路**。

## 3. 素材在哪 · 每个素材对应哪个问题

### 3.1 母版（4 条）

母版 = **干净原片 = GT 基准**。派生难例全部从母版合成，保证「已知正确答案」。

| ID | 物理位置 | 是什么 | 许可 | 判定（工具实测） | 解决哪个业务问题 |
|---|---|---|---|---|---|
| **M1_04** | `assets/raw/M1_04.mp4` | NASA 宇航员 Mark Vande Hei 单人访谈，1280×720，英文 | PD (NASA) | 单人正脸 **96%**、多人帧 0%、脸高 88px → **PASS** | **主 GT**：口型同步基准 + 正常字幕擦除基准 |
| **M3_01** | `assets/raw/M3_01.mp4` | Grace Hopper 1982 年演讲，654×480 老片 | PD (US Gov) | 单人正脸 92%、多人帧 0%、脸高 105px → PASS | **超分/修复**场景 + 字幕擦除（低清更难） |
| **M1_02** | `assets/raw/M1_02.mp4` | 竖屏采访 1080×1920 | CC BY-SA 4.0 | yaw 由 **−73°→−9°**，单人正脸仅 29%、多人帧 0%、脸高 126px | **侧脸口型崩坏**难例 |
| **M1_01** | `assets/raw/M1_01.mp4` | 户外多人对话 1920×1080 | CC BY 3.0 | 多人帧占比 **67%**、单人正脸仅 8%、脸高 210px | **多人场景**难例（字幕重叠、脸框跳变） |

> 数字口径：`python scripts/check_face.py assets/raw/<ID>.mp4`（默认 `--frames 24` 均匀采样），
> 与 `docs/notes/02-素材审计表.md`、`assets/manifest.json` 完全一致。
>
> 母版**不入库**（体积大且可再分发问题），由 `scripts/fetch_assets.py` 按 `assets/manifest.json` 里的 URL + SHA256 **确定性重建**。
> 许可、作者、来源链接逐条登记在 `assets/SOURCES.md`。

### 3.2 派生难例（每条母版 5 类 → 共 20 条 case）

case 集在 `assets/cases.json`，每条记录：GT 母版的 SHA256、派生文件名、用途、对应指标。

| 派生类型 | 怎么合成的 | 模拟的业务棘手 | 指标 |
|---|---|---|---|
| `hard_sub_bottom` | 底部烧一条硬字幕 | 已有硬字幕 → 擦除重绘 | 字幕区域 mask 内 PSNR/SSIM（对母版） |
| `hard_sub_face` | 字幕条**压到脸上** | 擦除是否伤及人脸 | 同上 + 人脸区单独看 |
| `low_bitrate` | `-b:v 400k` 重编码 | 低码率 → 超分 | SR 前后 PSNR/SSIM |
| `noisy` | `anoisesrc` + `amix` 加噪 | 噪声打崩 ASR → 字幕错 | ASR 字符错误率变化 |
| `mouth_occluded` | `drawbox` 遮住嘴部 | 嘴部遮挡 → LipSync 崩坏 | 口型同步指标 / 人工 MOS |

**组合矩阵**（4 母版 × 5 派生 = 20 条）：
`M1_04`(GT) / `M3_01`(低清) / `M1_02`(侧脸) / `M1_01`(多人)，各自派生上面 5 类。

### ❌ 未覆盖 / 已知缺口（**这是我要提醒你的重点**）

| 缺口 | 为什么重要 | 现状 | 补法 |
|---|---|---|---|
| **没有 B 站真实业务 Case** | JD 职责 2 白纸黑字写「结合**真实业务 Case**」 | 素材全是 Wikimedia Commons 公开素材，**不是 B 站内容** | 阶段二补：用 B 站**公开**可下载的官方内容（纪录片/动画），只作**本地实验不入库**；或用 B 站内容里的**问题类型**造等价样本，并明说等价 |
| **缺真实硬字幕素材** | 现在的硬字幕是**我用 FFmpeg 烧的**（合成），不是真实发行的字幕 | 待补 M2 | 从有正式字幕的公开视频取，或用 ASS 复刻真实字幕样式 |

| **缺动画/二次元画风** | JD 职责 1 明写「动画」，但口型同步在动画上方法完全不同 | 未覆盖 | 阶段二补 1 条 |
| **没有真实成本/耗时数据** | 职责 3 要求评估成本 | 翻译层已记账 token，但**没跑过真实 API** | 等 DeepSeek key |

### 我的判断（不粉饰）

> **素材解决的是「问题类型」，不是「真实业务内容」。**
> 我的强项是：真实问题被**拆成了可测量的 case**，每个 case 都有 GT、有指标、有留痕。
> 我的弱项是：JD 职责 2 想要「真实业务 Case」，我到 D2 还没碰到 B 站真实内容。
>
> **这是投递前必须补的**，而且不需要绕过版权——B 站有很多**官方公开**的可下载内容，
> 用来做**本地实验 + 报数字**是合规的（不传播、不入库、不商用），这正是我记忆里那条
> 「B 层素材：只本地实验、只报数字与结论」的策略。**但这需要你先确认是否接受**。
