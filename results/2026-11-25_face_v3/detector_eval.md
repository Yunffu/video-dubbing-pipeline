# 人脸字幕检测器评测（pipeline/face_sub.py）

这是**检测器本身的准确性证据**，跟 `table.md`（跑分）分开：
table.md 证明「擦得干不干净」，这份证明「擦的位置找得对不对」。

## 口径

不靠"看着对"，用**合成 GT 法造 oracle**：
派生件 = 母版 + 烧录字幕 → 两者逐像素相减（9 帧**时间中位数**消编码噪声，
单帧相减会被 h264 噪声淹没）→ 阈值化 = 字幕像素的精确位置 → 取 bbox = oracle 矩形。
检测矩形与 oracle 矩形求 **IoU**。

复跑：

```bash
python scripts/detect_face_sub.py assets/derived/M1_01_hard_sub_face.mp4 \
    --oracle assets/raw/M1_01.mp4 --json out.json
```

## 正负样本矩阵

三类样本各 4 条：
- **干净母版**（无字幕）→ 必须 `found=False`（不能瞎报）
- **人脸字幕派生件**（字幕压在嘴上）→ 必须 `found=True` 且 IoU 高
- **底部字幕派生件**（字幕在画面底部、不压脸）→ 必须 `found=False`
  （嘴/牙齿/下巴/衣物纹理是高密度，最容易误报的一类）

| case | 干净母版 | 人脸字幕 | 底部字幕 |
|---|---|---|---|
| M1_01 | found=False | found=True **IoU=0.923** | found=False IoU=0.0 |
| M1_02 | found=False | found=True **IoU=0.993** | found=False IoU=0.0 |
| M1_04 | found=False | found=True **IoU=0.975** | found=False IoU=0.0 |
| M3_01 | found=False | found=True **IoU=0.992** | found=False IoU=0.0 |

**12/12 判定正确**：正样本全检出且 IoU ≥ 0.92，两类负样本零误报。

## 逐条明细（det / oracle 矩形）

| case | 检测矩形 | oracle 矩形 | IoU |
|---|---|---|---|
| M1_01 face | [745, 427, 1056, 480] | [726, 428, 1057, 480] | 0.923 |
| M1_02 face | [239, 965, 640, 1027] | [237, 965, 641, 1027] | 0.993 |
| M1_04 face | [478, 259, 772, 306] | [477, 260, 772, 306] | 0.975 |
| M3_01 face | [142, 124, 494, 179] | [140, 124, 495, 179] | 0.992 |

误差形态：**高度几乎完全对齐（±1px）**，偏差集中在左右边界（最多 19px @M1_01）。
原因是行的合并阈值（0.30×脸高）把两行字幕之间的空隙并进来了，
左边界因此比 oracle 略窄 —— 这个偏差远小于字幕本身宽度，擦除无影响。

## 为什么底部字幕片不会被误判成压脸字幕

三条否决判据（缺一不算压脸字幕）：

1. **横向跨度 ≥ 1.5×脸宽** —— 嘴、牙齿、下巴只占 ~0.6 倍脸宽
2. **文字行必须跨过嘴**（嘴上方的衣服/背景纹理不算）
3. **文字块高度 ≥ 0.30×脸高**（实测压脸字幕 ≈0.55 倍脸高）

底部字幕的 y 坐标在画面底部，根本不落在「脸下半部」搜索区
（face_y + 0.25h ~ face_y + 1.40h）内 → 第一步就被筛掉。
