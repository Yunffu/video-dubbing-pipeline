## 一、场景一 · 赛博出海（中文硬字幕 → 擦除 → ASR → 英译 → 英配 → 成片）

链路：`assets/raw/S1_0x.mp4` → 擦字幕 → ASR(faster-whisper) → DeepSeek 翻译 → Edge-TTS 英配 → 音轨回贴 → 烧英字幕 → `final.mp4`

**S1_02**（854×480，40s，中文硬字幕）

| 阶段 | 结果 |
|---|---|
| 字幕带检测 | `(0, 404, 854, 460)`，方式 `bottom_band` |
| 擦除 | 1000 帧 / 42.7s（OpenCV Telea） |
| ASR | 13 段，zh，未降级 |
| 翻译 | DeepSeek，未降级 |
| TTS | en-US-AriaNeural，13 段 |
| 时间轴对齐 | 13 段全部拉伸，9 段超长，最大需求变速 4.25×（tempo 上限 1.25） |

**独立验收**（不依赖上面的日志，直接读成片）：
- 对 `final.mp4` 再跑一次 ASR → 出来的是**英文**："The little woman outside Zhengyangmen also got five nominations..."，说明画面已无中文原声字幕干扰，配的是英配。
- 字幕带亮像素（原片 → 擦后 → 成片）：`104/207/242/260` → `0/0/0/0` → `3468/3357/2395/4397`。擦干净，成片是我们自己的英字幕。

**S1_03**（854×480，28s）

第一版窗口（6–36s）只切出 3 段 ASR，原因查明：该窗口落在 VAD 的一个超长语音块里（5.0–35.74s）内部。改窗口到 35–63s（每 3s 一句的问答段）后 **9 段**，内容是《觉醒年代》陈独秀相关访谈，译文连贯。

- 擦除带 `(0, 332, 854, 436)`，700 帧 / 51.3s
- 译文示例："The Awakening Age is an excellent work / It tells history truly and vividly"
- 时间轴：9 段全部拉伸，4 段超长，最大需求变速 1.69×

## 二、场景二 · 合法搬运（外片硬字幕 → 擦除 → 换授权字幕 + 本地化配音）

**S2_01**：英文内容 + **日文**硬字幕 → 擦日字幕 → 换成中文字幕 + 中文配音。

- 字幕带 `(0, 572, 1280, 688)`，751 帧 / 65.3s
- ASR 5 段（en）→ DeepSeek 英译中 → Edge-TTS zh-CN-XiaoxiaoNeural
- 译文抽检："the Faculty of Engineering…" → "工学部，以及不久后的工学研究科。"
- 亮像素：原片 `10499/6641/12345/16771` → 擦后 `0/0/1332/2812` → 成片 `5041/4618/9784/12170`
  （残留那两帧是 OpenCV inpaint 在高亮背景上的边缘痕迹，不是字形）

**S2_03**：720×1280 竖屏，原片自带**中文字幕**，处理后换成本地化中字幕 + 中配。

- 字幕带 `(0, 892, 720, 1092)`（竖屏，坐标在 1280 高的画面里）
- 亮像素：原片 `10137/12671/8671/11910` → 擦后 `599/0/0/0` → 我们烧的新字幕落在底部 `1150–1250` 行，`8010–8678` 像素
- 译文抽检："来到中华人民共和国。本周我在加州旧金山，与拜登总统和布林肯国务卿…"

> **踩坑记录（已修）**：S2_01 最初擦错了区域 —— face 检测器在画面右侧返回了误检矩形 `[897,306,1135,337]`，而日文字幕其实在 rows 603–678。证据是擦完的字还在。
> 修法：`detect_region` 改成**先底部字幕带、后 face**（底部带是更稳的先验），face 只在没有底部带时才用。教训已写进 `scripts/scenario_demo.py` 的函数注释。

## 三、场景三 · 内部创作者工具（方案A vs 方案B 对比表）

产物：`s3/compare_table.md`（人读）、`s3/compare_table.json`（机读）、`s3/broken_repairs.md`、`s3/*_compare.png`

口径：**同一 mask、同一帧序列，只换修补引擎**。有合成 GT 的派生件算「修补结果 vs 母版」（PSNR/SSIM in-mask），真实素材只能算闪烁比。

### 合成 GT 派生件（8 个）

| 案例 | opencv_telea PSNR in | lama_onnx PSNR in | LaMa 快慢 |
|---|---|---|---|
| M1_01 bottom | 16.60 | **19.23** | 7.5s vs 0.85s（慢 8.8×） |
| M1_01 face | 18.35 | **19.22** | 12.9s vs 0.42s（慢 31×） |
| M1_02 bottom | **21.93** | 16.41 | 5.1s vs 0.95s |
| M1_02 face | 22.06 | 19.97 | 4.5s vs 0.43s |
| M1_04 bottom | 16.11 | **17.68** | 4.2s vs 0.38s |
| M1_04 face | 17.10 | **20.02** | 4.2s vs 0.20s |
| M3_01 bottom | 18.78 | 17.18（SSIM **0.863** 最高） | 2.7s vs 0.18s |
| M3_01 face | 22.48 | **23.27** | 2.8s vs 0.13s |

**结论**：
1. **mask 外三者都是 99.0 dB** —— 三种引擎都不误伤画面，硬约束全过。质量差异**只在字幕区内部**。
2. LaMa 在 **face 字幕上稳定占优**（+0.9 ~ +2.9 dB，SSIM 同步涨），因为人脸/复杂背景是边缘扩散最吃亏的场景。
3. LaMa 在 **bottom 字幕上不稳定**：M1_02 反而掉 5.5 dB（M1_02 是 1080p，字幕带 392 行高，LaMa 一个 512 窗口盖不全）。
4. 代价：**慢 8~31 倍**。720p RTF 从 3.3~23.9 变成 68~322（RTF>1 = 比实时慢）。

### 真实素材（闪烁比）

| 素材 | 引擎 | ms/帧 | flicker in | flicker out | 比值 |
|---|---|---|---|---|---|
| S1_02 | opencv_telea | 220 | 34.07 | 26.76 | 1.273 |
| S1_02 | lama_onnx | 2764 | 35.75 | 26.76 | 1.336 |
| S2_01 | opencv_telea | 343 | 62.23 | 61.04 | 1.019 |
| S2_01 | lama_onnx | 4247 | 60.32 | 61.04 | 0.988 |

闪烁比 ≈ 1 → **两个引擎在真实素材上都没有出现"逐帧乱跳"**，动画/运动镜头的涂抹问题在本批素材上没被触发。

### 给 Leader 的一句话

> 方案B（内部 API / 内容感知模型）的收益是**明确的**：人脸字幕上 PSNR +1~3 dB，且不会把画面外的像素碰坏。
> 它的代价是**确定的**：CPU 上慢一个数量级（RTF 70–320），并且**在底部字幕上不保证更好**（有一例反而更差）。
> 建议：**按字幕类型分流** —— 检测到人脸字幕走方案B，底部字幕走方案A（或走方案B 但接受 5× 时延）。

## 五、本轮新增的量化结论：收紧底部 mask 值不值

`results/mask_tighten_eval.json`（脚本 `scripts/mask_tighten_eval.py`）。三组对照：**同一引擎、同一批帧**，只换 mask。

| 案例 | 粗带面积 | 粗带文字召回 | 收紧面积 | 收紧文字召回 | PSNR in：粗 → 收紧 |
|---|---|---|---|---|---|
| M1_01 bottom | 0.207 | 1.000 | 0.158 | 0.994 | 16.84 → **17.08** |
| M1_02 bottom | 0.204 | 1.000 | 0.147 | 0.928 | 21.89 → 16.65 |
| M1_04 bottom | 0.211 | 1.000 | 0.151 | 0.956 | 16.11 → 15.61 |
| M3_01 bottom | 0.267 | 1.000 | 0.181 | 0.956 | 18.99 → 17.32 |

**结论：收紧是负收益，默认不开启。**
- 面积只省 21~31%，但文字行召回掉到 **0.928~0.994**（烧录字幕是**两行**，行间有约 15px 的密度低谷，收紧时容易只留一行）。
- 漏掉的行 = 擦不干净的字，4 个案例里 **3 个 mask 内 PSNR 反而下降**（M1_02 掉 5.2dB、SSIM 从 0.773 掉到 0.517）。
- 生产链路已改为**默认用粗带**；需要减 inpaint 面积时设 `VD_TIGHTEN_BAND=1` 打开。

## 七、已知局限（诚实清单）

1. **ASR 用的是 `small` + int8 + CPU**，广播级中文仍有错字（S1_02 把「飾演蘇大強的倪大紅」听成「試驗蘇家負責的尼大紅」）。上 `medium` 能修，但 CPU 上每分钟视频要多花十几秒。
2. **时间轴对齐靠变速（atempo）**，超出 0.8~1.25 倍的段只能硬拉伸。S1_02 最大需求变速 4.25×，说明**英译后文本天然比中文长**，这是译文长度不匹配的量化证据，不是 bug。真实业务需要配"改写/精简"或"分句"策略。
3. **真实素材没有 GT**，只能看闪烁比和耗时，"擦得好不好"目前没有严格指标（场景三第一部分用合成 GT 补了这个洞）。
4. **`S2_02`（动画，Spooky Month Short）未能跑通**：全局字幕带检测在动画上命中不到（hit_ratio 0.08），且字幕只出现在 290–380 帧。检测器需要动画专用分支，暂列为待办。
5. **LaMa 在 CPU 上不可用于全量生产**：RTF 70–320，只适合"按需修脸"。
